## Every language is a deal

A processor only follows tiny instructions: add two numbers, copy this, jump there. Nobody writes
those by hand anymore. People write code in a programming language, and another program turns it
into instructions the processor can follow. Each language decides how that happens, and every
decision gives you something and takes something away. No language wins every decision, so people
keep making new ones for the jobs the old ones handle badly. [PLDB](https://pldb.io/), a public
database of languages, lists more than 3,400 programming languages.

Think of an online shop. The page you click on runs JavaScript in your browser. The server behind it
might run Go or Python. The orders sit in a database you ask questions in SQL. Three places, three
languages, because each place wants something different. This site calls those places **slots**,
and every language card says how well the language fills each of the 13.

## Why new languages keep appearing

Most languages that lasted were built by people stuck on a concrete problem. Read in order, those
problems show what slowed programmers down in each period.

- **1957: programmers cost too much.** Programs were written by hand as rows of zeros and ones.
  IBM's history of Fortran says programmers cost at least as much as the computers and
  [spent up to half their time debugging](https://www.ibm.com/history/fortran). Fortran let
  scientists write formulas and left the zeros and ones to a compiler.
- **1958 to 1959: new kinds of work.** John McCarthy wanted a language for
  [artificial intelligence work](http://www-formal.stanford.edu/jmc/history/lisp/node2.html) and
  built Lisp. COBOL came from a US Department of Defense push for a business language, in
  [English-like words, that worked across computers](https://www.ibm.com/think/topics/cobol).
- **1972: an operating system people could read.** Unix was first written in the processor's own
  instructions. B had no types and fit the PDP-11 badly, so Dennis Ritchie added types and wrote C,
  and in 1973 the [Unix kernel was rewritten in it](https://csapp.cs.cmu.edu/2e/docs/chistory.html).
- **1979: big programs that still had to be fast.** Simula let Bjarne Stroustrup group data with
  the code that works on it, but it [simply ran too slow](https://stroustrup.com/gillies.htm), so
  he added that idea to C, and it became C++.
- **1989 to 1995: the programmer's time, many devices, the web.** Python started as a
  [scripting language for Unix and C programmers](https://www.python.org/doc/essays/foreword/), Java
  for [devices with different processors](https://ibiblio.org/java/slides/hope/02.html), and
  JavaScript for [pages in the Netscape browser](https://brendaneich.com/2008/04/popularity/).
- **2006 to 2015: security holes from memory mistakes.** Microsoft estimates that 70% of the
  security holes in its code come from
  [memory errors in C and C++](https://www.technologyreview.com/2023/02/14/1067869/rust-worlds-fastest-growing-programming-language/).
  Rust checks memory use before the program runs, and Mozilla used it inside Firefox.
- **2007 to 2012: huge codebases.** At Google one program took
  [45 minutes to build](https://go.dev/talks/2012/splash.article), and Go was designed to build
  fast. Microsoft built TypeScript because large JavaScript apps were
  [simply too difficult to build](https://www.theregister.com/software/2012/11/03/microsoft-typescript-isnt-a-javascript-killer/717785).
- **2024: graphics cards.** A GPU has thousands of small cores. Bend promised code that reads like
  Python yet runs on a GPU with
  [zero explicit parallel annotations](https://web.archive.org/web/20240520212438/https://github.com/HigherOrderCO/Bend),
  so the programmer does not split the work by hand. Its GPU version ran only on Nvidia cards.
  On [17 September 2026](https://github.com/bendlang/bend/blob/main/CHANGELOG.md) its makers
  released Bend 2, a different language, and [Bend 1 programs do not run on it](https://github.com/bendlang/bend).

## What slows people down now

AI now writes a large share of new code. In October 2024 Google said that
[more than a quarter of all new code at Google is generated by AI](https://blog.google/inside-google/message-ceo/alphabet-earnings-q3-2024/),
then reviewed and accepted by engineers. Every one of those changes still has to be checked by
someone.

One answer is a **proof** that a computer checks: you write down rules, and a program called a
proof checker confirms that the code keeps them, with no person reading the code. Amazon used
this on its permissions language Cedar: it
[modeled Cedar in Lean and proved important properties of its design](https://arxiv.org/abs/2403.04651).
Bend 2 builds the whole language around it. Its README asks "How can you trust AI code, without
reading it?" and answers ["By forcing your AI to write a correctness proof"](https://github.com/bendlang/bend);
the agent writes the proofs and runs the checker before every commit.

Bend 2 is young, and its own README lists the limits. It aims to run as fast as C on one
processor core and to use the GPU on Nvidia cards and Macs; it turns each program into one C file
or into JavaScript, and its makers say it works best on servers, on Linux or macOS. Text
processing is slow, there is no JSON or HTTP library yet, proving theorems takes extra effort, and
the compiler is 99% written by AI and not yet fully audited
([Bend README](https://github.com/bendlang/bend)). A new language is also new to the AI models
that are meant to write it, so the README tells agents to run `bend guide` to learn it.

## How the code gets run

There are three common ways, and they decide speed and convenience.

- **Compiled ahead of time.** A compiler turns the whole program into machine code before it runs.
  The result starts fast and runs fast, but every change needs a new build, and you build once per
  kind of computer. C, C++, Rust, Go and Swift work this way.
- **Compiled for a virtual machine.** The compiler produces bytecode for a pretend computer, the
  virtual machine, which runs on many real ones. Java's class files are
  [hardware- and operating system-independent](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-1.html).
  The virtual machine has to be installed and costs memory. Java, Kotlin, C# and Elixir work this way.
- **Interpreted.** An interpreter reads the code and carries it out while the program runs. Nothing
  has to be built, so you change a line and run it again at once, but the extra layer makes it
  slower. Python, Ruby, PHP, Lua and Bash work this way.

TypeScript takes a fourth road: it is translated into JavaScript, which the browser then runs.

## Who cleans up memory

A running program keeps borrowing memory and has to give it back, or the computer runs out. The
[Rust book](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html) sums up the three
classic answers: some languages have garbage collection that looks for memory no longer in use
while the program runs, in others the programmer frees memory by hand, and Rust uses ownership
rules that the compiler checks.

- **By hand** (C, C++, Zig): nothing runs in the background, so the program is small and its timing
  is exact. One forgotten step can crash it or open a security hole.
- **A garbage collector** (Java, Go, JavaScript, C#): a whole family of bugs disappears, but the
  collector needs memory and time of its own and runs when it decides to.
- **Reference counting** (Swift, Python): each piece of memory counts its users and frees itself when
  the count reaches zero.
- **Ownership** (Rust): the compiler proves the program frees everything correctly. No collector runs,
  but the rules take a while to learn.

## Checked before or while running

Every value has a kind: a number, a piece of text, a list. A language with **static types** checks
that kinds match before the program runs; TypeScript calls itself a
[static type checker](https://www.typescriptlang.org/docs/handbook/typescript-from-scratch.html)
for this reason. A language with **dynamic types** checks while the program runs, so writing is
quicker and some mistakes show up only when that line runs. Python allows type hints, but
[no type checking happens at runtime](https://peps.python.org/pep-0484/); a separate tool checks them.

## Doing many things at once

A web server may talk to ten thousand visitors at the same moment. Languages handle that in
different ways: threads managed by the operating system (Java, C++), lighter threads managed by
the language itself, such as Go's [goroutines](https://go.dev/doc/effective_go), async code that
starts slow work and moves on until it finishes (JavaScript), or small isolated workers that only
send each other messages, like Elixir's [processes](https://hexdocs.pm/elixir/processes.html).

## So why can't one language do everything?

Because of those deals, and because every place where code runs has its own rules. A language
tuned to be quick to write pays for it in speed. A language that gives exact control over memory
makes mistakes easier. A browser accepts only JavaScript and WebAssembly. When a language does not
fit a slot, its card names one of the seven reasons below.
