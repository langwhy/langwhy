## Why it exists

In 2010 José Valim was on the Rails core team, working on Rails thread-safety guarantees. His company later wrote that "because of that experience, he felt solving concurrency problems was too hard", so hard that it was difficult to keep Ruby's philosophy of programmer happiness while solving them ([Plataformatec](https://blog.plataformatec.com.br/2015/01/introducing-elixir-radar-the-weekly-email-newsletter-about-elixir/)). He went to study other platforms and "fell in love with the Erlang VM": its concurrency model and its failure semantics, which showed him how to write code that survives errors without being defensive. At the beginning of 2011 Plataformatec agreed he could spend all his time on a new language for that VM ([Plataformatec](https://blog.plataformatec.com.br/2015/01/introducing-elixir-radar-the-weekly-email-newsletter-about-elixir/)). Valim has also said that the BEAM was the main reason he built Elixir ([ERLEF interview](https://erlef.org/blog/eef/behind-elixir-interview-with-jose-valim)). In May 2012 Elixir v0.5.0 was announced on the Erlang mailing list ([erlang-questions](https://erlang.org/pipermail/erlang-questions/2012-May/066994.html)).

## What it trades away

Elixir gets Erlang's process model and fault tolerance, and pays for it in speed on CPU-heavy work and in dynamic typing, where type mistakes show up at run time. OTP's supervision trees are a separate model to learn before the language feels natural. The project's own pitch is strongest for "message-oriented and web real-time systems" ([Elixir](https://elixir-lang.org/)), which is the region where the trade pays off. Outside it, a statically typed or native language is usually the better fit.

## Where it won

Discord's core services run on Elixir. Its 2019 post on scaling to 11 million concurrent users explains that the sorted set it needed for very large servers is written in Rust and exposed to Elixir as a NIF, so the core stays Elixir ([Discord engineering](https://discord.com/blog/using-rust-to-scale-elixir-for-11-million-concurrent-users)). Nerves uses Elixir and the BEAM to build production embedded systems ([Nerves](https://nerves-project.org/)). Bleacher Report moved its Team Stream app from Ruby to Elixir, according to a case study by Erlang Solutions, the consultancy that did the work ([Erlang Solutions](https://www.erlang-solutions.com/case-studies/bleacher-report-case-study/)). That source is vendor-written, so its server figures are self-reported.
